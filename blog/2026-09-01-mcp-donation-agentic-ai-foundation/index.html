Anthropic Donates MCP to the Agentic AI Foundation — What It Means for Builders

The Model Context Protocol moves to shared stewardship under the Linux Foundation. Here's what changes for developers shipping on MCP today.

By Ashrey · Chief Architect, The Agent Lab

On December 9, 2025, Anthropic announced it is donating the Model Context Protocol to the Agentic AI Foundation (AAIF), a directed fund under the Linux Foundation co-founded by Anthropic, Block, and OpenAI, with support from Google, Microsoft, AWS, Cloudflare, and Bloomberg. The protocol that started as an Anthropic-led specification now has a governance structure designed to survive any single company's roadmap.

For developers building on MCP today, the donation is not a symbolic gesture. It changes how the spec evolves, who decides what goes in the next release, and whether the protocol can become a neutral substrate the way HTTP did for the web. Here's what matters.

The Governance Model

The Agentic AI Foundation is a directed fund, not a traditional open-source foundation. Directed funds under the Linux Foundation operate with a narrower charter and a steering committee that represents the founding contributors. In this case, the steering committee includes representatives from Anthropic, Block, and OpenAI, with the Linux Foundation providing legal, administrative, and trademark infrastructure.

This structure matters because MCP's previous governance was effectively "Anthropic decides, community comments." The spec repository accepted PRs, but the roadmap, breaking changes, and release cadence were internal to Anthropic. The AAIF charter requires consensus among steering committee members for major decisions, which means OpenAI and Block now have veto power over breaking changes.

For builders, this reduces the risk of a single vendor steering the protocol toward their proprietary extensions. It also means the spec process will slow down — consensus among three well-resourced companies takes longer than one company's internal review.

What Changes for the Spec

The immediate practical changes:

  • Trademark and IP. The MCP name and marks move to the Linux Foundation. No single company can claim ownership or restrict usage.
  • Specification repository. The spec moves from modelcontextprotocol/specification to a foundation-owned repository. The existing GitHub organization modelcontextprotocol transfers to AAIF.
  • Release process. Future releases go through a steering committee review. The 2026-07-28 spec (the first major revision in 20 months) was the last Anthropic-only release.
  • Contribution policy. A formal contributor license agreement (CLA) will be required. The foundation will publish contribution guidelines and a code of conduct.

The spec itself does not change overnight. The 2026-07-28 release — stateless HTTP transport, JSON-RPC batching, improved primitives — remains the current baseline. What changes is who authorizes the next one.

Why OpenAI and Block Joined

OpenAI donated AGENTS.md, their agent configuration format, to the same foundation. Block donated goose, their agent framework. This is not altruism — it's strategic positioning.

OpenAI needs MCP to succeed as a neutral layer because their Agents SDK now supports MCP natively. If MCP were perceived as "Anthropic's protocol," enterprise buyers would hesitate. By co-founding the foundation, OpenAI gets a seat at the table and ensures the protocol stays compatible with their stack.

Block's goose framework is built on MCP. They need the protocol to remain stable and vendor-neutral to justify their investment. Their participation also signals that fintech-grade governance matters — Block operates in regulated environments where single-vendor dependencies are a compliance risk.

Google, Microsoft, AWS, Cloudflare, and Bloomberg are listed as supporters, not co-founders. Their involvement suggests they want MCP to become the default integration layer for enterprise AI tooling, similar to how Kubernetes became the default for container orchestration after the CNCF donation.

What This Means for Your MCP Server

If you maintain an MCP server today, nothing breaks. The protocol is stable. But three practical shifts are worth planning for:

1. Expect a Formal Conformance Suite

The CNCF model for Kubernetes includes a conformance certification. The AAIF will likely publish a similar test suite for MCP servers. If you want to advertise "MCP compatible," you'll need to pass it. Start treating the spec as a contract, not a suggestion.

2. Extension Process Will Formalize

Today, custom tools and resources are informal. The foundation will likely define an extension registry and a process for proposing standard extensions. If you've built proprietary extensions, plan to either contribute them or maintain them as clearly vendor-specific.

3. SDK Support Will Broaden

Anthropic's Python and TypeScript SDKs are the reference implementations. The foundation will encourage alternative SDKs in other languages. If you've been waiting for a Go, Rust, or Java SDK, the timeline just accelerated — but the foundation won't write them. The community will.

The Risk: Design by Committee

The Linux Foundation has a strong track record with Kubernetes, but also a track record of specs that grow until they collapse under their own weight (see: some OASIS standards). Three well-funded companies with different product strategies can produce a spec that satisfies everyone and delights no one.

The mitigating factor: MCP's scope is intentionally narrow. It's a wire protocol for tool calls, resources, and prompts. It does not define agent behavior, memory, planning, or evaluation. The narrower the scope, the harder it is to bloat.

Watch the first post-donation spec release. If it adds significant surface area without clear implementer demand, the committee dynamic is winning. If it fixes sharp edges from 2026-07-28 and adds the conformance suite, the governance is working.

What to Do This Week

  1. Audit your server against the 2026-07-28 spec. The stateless HTTP transport and JSON-RPC batching are the new baseline. If your server still uses the old session-based transport, plan the migration.
  2. Read the AAIF charter when published. The Linux Foundation will publish the governing documents. The steering committee composition, voting rules, and extension process will be in there.
  3. Track the spec repository transfer. Watch modelcontextprotocol/specification for the move. Update your dependency references when the new URL is announced.
  4. Ignore the hype. The donation is a governance event, not a product launch. Your MCP server works today exactly as it did yesterday.
